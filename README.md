# SARS-CoV-2 Wastewater Genomic Surveillance Visualization Pipeline
Washington state Department of Health, Molecular Epidemiology Program, SARS-CoV-2 Wastewater Genomic Surveillance

## Overview

This repository contains a workflow for analysis of Sars-CoV-2 wastewater surveillance data. Freyja ouputs, sample site data, and population density data are integrated to produce plots showing trends in Sars-CoV-2 variant proportions in environmental samples. The workflow runs on snakemake using containerized environments for reproduceability and ease of setup.

Report generation is performed by populating a user-generated markdown template with values from a configuration file and plots generated by the workflow. This report is then converted into an HTML document as well as a Latex-formatted PDF.

Future work:

## How to Use

### Prerequisites
1. Ensure all dependencies are installed
2. Have your data sources ready in their respective locations

### Step-by-Step Instructions

#### Run the QC Workflow
It's a good idea to run the quality control portion of the workflow before running the full analysis. Issues with data formats, pango lineage classifications, and population-density weighting will be apparent in `full_qc_report.txt`. 

In a terminal window, navigate to `wamep-sarscov2-wastewater/`. The following command will run the snakemake workflow, targeting only the QC report with the argument `final_qc`, assigning 6 cores with `--cores 6`, and executing with a container via `--use-singularity`. The `--config copy=n` argument will leave the new runs placed in `new_runs/`, rather than combining with historical data sets.
```
snakemake final_qc --cores 6 --use-singularity --config copy_runs=n
```
The following dag shows the steps (snakemake rules) involved in the QC run. This excludes the steps involved in plotting and generation of the final report.

![DAG showing the Quality Control Workflow](./qc_dag.svg "DAG of QC Workflow")

Results are located in `full_qc_report.txt` in the main directory.

#### 1. Pre-QC Check
**Important**: This ouput only reports on quality of data in the `new runs` folder. Data are checked for formatting to ensure compatibility with downstream analyses, including:
  - Missing data points
  - Dates are recent (last 30 days) and formatted YYYY-MM-DD.
  - Dates are unique
  - Sample Sites are screened for new values
  - Variant proportions are sensible
  - Sample ID's are unique
Any violations of the above will be apparent in the report.

Fix any issues before going further.

#### 2. Variant Mapping QC Check (Second Priority)
This section of the QC report reports results of the following checks:
- Check Parent Lineage Mapping
- Check Hexcode Mapping
- Check Recombinants
- Check for Ancestrals

#### 3. Population Weights Validation (Third Priority)
- After population weights are applied to variant proportions, verify:
  - **Statewide**: Check `check_sums_statewide` - each week sums to 1
  - **County-level**: Check `check_sums_county` - each county sums to 1

### Running the Full Worlflow
The following command will run the full workflow, including all quality-control steps and data analysis/report generation. By default, all runs placed in `new_runs/` will be moved to `runs/`. 

From the main directory, run:
```bash
snakemake --cores <N> --use-singularity
```
The dag describes the workflow. Note the QC steps in addition to the full plotting and reporting workflow.

![DAG showing the Quality Control Workflow](./dag.svg "DAG of Full Workflow")

#### Outputs:
The full workflow produces a final QC report, plots and reports. The final reports are available in three formats in the main directory:
- `ww_report.html`
- `ww_report.md`
- `ww_report.pdf`

#### Figure Quality Control
It's important, even with thorough quality control steps, to ciritically evaluate the results and plots to ensure sensible inference and conclusions. This workflow aims to make reporting reproducable, not automatic.
